# Telegram Chat Summarizer Bot (TypeScript)

[English version](../README.md)

Асинхронный Telegram-бот на базе Node.js, TypeScript и фреймворка `telegraf` для автоматического логирования и суммаризации сообщений в групповых чатах. Из коробки работает с **Gemini 3.1 Flash Lite** от Google (через официальный SDK `@google/genai`) и может быть подключён к любому **OpenAI-совместимому API** (OpenAI, OpenRouter, Together, локальные серверы vLLM/Ollama и т.д.).

**ОСТОРОЖНО!! Стопроцентный ИИ слоп проект**, написанный Джеминаем 3.5 Флэш с нуля. Использовать с осторожностью.

## Особенности
*   **Сменный LLM-провайдер**: По умолчанию использует Google Gemini, но может работать с любым OpenAI-совместимым эндпоинтом Chat Completions (OpenAI, OpenRouter, локальные серверы и т.д.) через `LLM_PROVIDER=openai`. Модель настраивается для обоих провайдеров.
*   **Поддержка нескольких языков**: Настраиваемый язык интерфейса бота и суммаризации (полностью поддерживаются английский и русский языки; см. настройки `.env`). Поддерживает естественные запросы времени на обоих языках.
*   **Логирование в реальном времени**: Бот отслеживает и записывает текстовые сообщения и подписи к медиафайлам в локальную базу данных SQLite.
*   **Синхронизация редактирования**: Автоматически обновляет текст в базе данных, если пользователь отредактировал свое сообщение в Telegram.
*   **Безопасность для памяти**: Фоновый процесс раз в сутки очищает сообщения старше 30 дней.
*   **Безопасные права доступа базы данных**: Создает директорию базы данных с правами `0700`, если ее еще нет, и выставляет файлу БД права `0600` на Linux/macOS.
*   **Защита разметки**: Очищает ответ модели до безопасной Telegram HTML-разметки, конвертирует базовую Markdown-разметку и переключается на обычный текст, если Telegram все равно отклоняет форматирование.
*   **Совместимость с темами (Threads)**: Корректно сохраняет `thread_id` для форумных супергрупп.
*   **Поддержка личных чатов**: В личных чатах запросы с триггерными словами запускают суммаризацию, а остальные сообщения получают короткое приветствие/подсказку.
*   **Понимание медиа (мультимодальность)** *(по желанию, только Gemini)*: Когда включено, бот логирует и передаёт модели изображения, голосовые сообщения и кружки, чтобы выжимки отражали их содержимое, а не только текст. По умолчанию выключено; включается по типам через флаги `MULTIMODAL_*`.
*   **Углублённые ответы (deep-dive)** *(по желанию)*: Когда включено, упоминание бота с конкретным вопросом (например, *«@bot почему мы отложили релиз?»*) возвращает точечный ответ по истории чата вместо стандартной структурированной суммаризации. По умолчанию выключено; включается через `DEEP_DIVE_ENABLED=true`.

## 🛠️ Подготовка и настройка бота

### 1. Создание бота в Telegram
1. Напишите боту [@BotFather](https://t.me/BotFather) в Telegram.
2. Создайте нового бота с помощью команды `/newbot`, скопируйте полученный **Telegram Bot Token**.

### 2. Отключение приватности (Важно!)
По умолчанию Telegram-боты не могут читать сообщения в группах, кроме прямых упоминаний. Чтобы бот мог накапливать историю для суммаризации:
1. В чате с [@BotFather](https://t.me/BotFather) отправьте команду `/mybots` и выберите вашего бота.
2. Перейдите в **Bot Settings** -> **Group Privacy**.
3. Нажмите **Turn off** (вы должны увидеть сообщение `Privacy mode is disabled`).
4. Если бот уже был добавлен в группу, **удалите его и добавьте заново**, чтобы настройки применились.
5. *(Рекомендуется)*: Сделайте бота администратором в группе и выдайте ему разрешение на чтение сообщений (Read messages).

### 3. Получение API-ключа LLM
Для провайдера по умолчанию (Gemini) получите бесплатный или платный ключ API в [Google AI Studio](https://aistudio.google.com/). Либо установите `LLM_PROVIDER=openai` и укажите `OPENAI_API_KEY`, чтобы использовать OpenAI или любой OpenAI-совместимый эндпоинт (см. настройки LLM-провайдера ниже).

### 4. Дополнительная настройка (Опционально)
Вы можете выбрать LLM-провайдера, настроить ограничения частоты запросов (rate limiting), режим минимизации личных данных (PII) и белый список разрешенных чатов в вашем файле `.env` для защиты квоты API:
*   **LLM-провайдер**:
    *   `LLM_PROVIDER`: `gemini` (по умолчанию) или `openai`. При значении `openai` бот обращается к OpenAI-совместимому эндпоинту Chat Completions вместо SDK Gemini.
    *   `GEMINI_MODEL`: Переопределяет модель Gemini (по умолчанию `gemini-3.1-flash-lite`).
    *   `OPENAI_API_KEY`: Ключ API для OpenAI-совместимого провайдера (обязателен при `LLM_PROVIDER=openai`).
    *   `OPENAI_MODEL`: Название модели для OpenAI-совместимого провайдера (по умолчанию `gpt-4o-mini`).
    *   `OPENAI_BASE_URL`: Произвольный эндпоинт для OpenAI-совместимых провайдеров (по умолчанию `https://api.openai.com/v1`, завершающий слэш не нужен). Работает с OpenRouter, Together, локальными серверами vLLM/Ollama и т.д.
*   **Ограничение частоты запросов (Rate Limiting)**:
    *   `RATE_LIMIT_MAX_REQUESTS`: Задает максимальное количество запросов суммаризации, разрешенных для одного чата за указанный интервал времени. Функция отключена, если переменная не задана или равна `0`; некорректные или отрицательные значения работают в fail-closed режиме и временно блокируют запросы.
    *   `RATE_LIMIT_WINDOW_SEC`: Длительность окна ограничения в секундах (по умолчанию `3600` секунд — 1 час; некорректные значения заменяются на `3600`).
*   **Авторизация чатов**:
    *   `ALLOWED_CHATS`: Список идентификаторов (ID) чатов через запятую, которым разрешено использовать бота (например, `-100123456789,-100987654321,12345678`).
    *   `ALLOWED_USERS`: Список идентификаторов (ID) пользователей Telegram через запятую, которым разрешено общаться с ботом в личных сообщениях (DMs). Если параметр задан, он ограничивает личные сообщения даже при установленном `ALLOW_ALL_CHATS=true`.
    *   `ALLOW_ALL_CHATS`: Установите значение `true`, чтобы явно отключить проверку авторизации и разрешить все чаты. По умолчанию авторизация работает по принципу **fail-closed** (запрещено по умолчанию): если переменная `ALLOW_ALL_CHATS` не установлена в `true` и оба списка `ALLOWED_CHATS` и `ALLOWED_USERS` пусты или не заданы, все чаты будут заблокированы по умолчанию.
*   **Минимизация личных данных (PII)**:
    *   `REDACT_USER_IDENTITIES`: Установите значение `true`, чтобы включить обезличивание участников в истории сообщений. В этом режиме реальные имена и юзернеймы в заголовках и текстах сообщений заменяются стабильными псевдонимами (например, `User 1`, `User 2`), а любые другие упоминания юзернеймов заменяются на `@user_redacted`.
*   **Ссылки на сообщения**:
    *   `INCLUDE_MESSAGE_LINKS`: Установите значение `true`, чтобы добавлять ссылку на исходное сообщение для каждой темы в разделе «Основные темы обсуждения». Работает только в приватных супергруппах и каналах (ссылки вида `t.me/c/…`); обычные группы и личные чаты пропускаются автоматически. По умолчанию: `false`. Независимо от `REDACT_USER_IDENTITIES`.
*   **Мультимодальность (медиа)** (только Gemini — не действует при `LLM_PROVIDER=openai`, на старте выводится предупреждение):
    *   `MULTIMODAL_ENABLED`: Главный переключатель (по умолчанию: `false`). Должен быть `true` для любого логирования/обработки медиа; пока он выключен, флаги по типам ниже игнорируются.
    *   `MULTIMODAL_IMAGES_ENABLED` / `MULTIMODAL_VOICE_ENABLED` / `MULTIMODAL_VIDEO_NOTE_ENABLED`: Переключатели по типам (по умолчанию: `false` каждый) для изображений, голосовых сообщений и кружков.
    *   `MULTIMODAL_INCLUDE_BY_DEFAULT`: Если `true`, медиа всегда включается в выжимки. Если `false` (по умолчанию), медиа включается только когда запрос об этом упоминает (например, *с медиа*, *войс*, *кружки*, *with images*).
    *   `MEDIA_STORAGE_MAX_MB`: Лимит диска под хранимые медиафайлы (по умолчанию: `500`). При превышении сначала удаляются самые старые файлы.
    *   `MULTIMODAL_FILES_API`: Как медиа передаётся в Gemini — `off` (по умолчанию; inline base64 с консервативными капами 1 МБ изображение / 3 МБ голосовое / 5 МБ кружок), `ondemand` (загрузка в Gemini Files API во время суммаризации, без inline-капов) или `cache` (как `ondemand`, но переиспользует загруженный URI между суммаризациями в пределах ~48ч хранения у Google).
    *   `MEDIA_MAX_DOWNLOAD_MB`: При включённом Files API заменяет покапные inline-лимиты единым капом (по умолчанию: `20` — потолок Telegram Bot API для `getFile`).
*   **Углублённые ответы (deep-dive)**:
    *   `DEEP_DIVE_ENABLED`: Установите значение `true`, чтобы включить режим углублённых ответов (по умолчанию: `false`). Когда включено, упоминание/личное сообщение с вопросительным маркером (например, *что, почему, как, расскажи, what, why, how*) обрабатывается как конкретный вопрос вместо стандартной суммаризации; упоминание без маркера по-прежнему даёт обычную суммаризацию. При явном таймфрейме ответ строится по сообщениям этого окна; без таймфрейма переиспользуется последняя закэшированная суммаризация чата (хранится до 3 дней), иначе — последние 24 часа. Deep-dive анализирует **только текст** — даже при включённой мультимодальности медиа в этом режиме модели не передаётся.
*   **Логирование**:
    *   `DEBUG=true`, `DEBUG=1` или `LOG_LEVEL=debug`: Включает DEBUG-логи. Логи остальных уровней выводятся всегда.
*   **Путь к базе данных**:
    *   `DB_PATH`: По умолчанию `data/bot_messages.db`. Значения с `..` отклоняются при запуске.
*   **Ключ Gemini API**:
    *   `GEMINI_API_KEY`: Основная переменная для API-ключа. `GOOGLE_API_KEY` также поддерживается как fallback.

## 🚀 Установка и запуск

Подробные инструкции по развертыванию бота на серверах Debian/Ubuntu и Alma/Rocky Linux см. в [Руководстве по развертыванию](deployment_ru.md).

### Требования
*   Node.js v20.17.0 или выше (протестировано на Node.js v22)

### Шаги установки

1.  Клонируйте репозиторий и перейдите в его папку.
2.  Установите необходимые зависимости с помощью npm:
    ```bash
    npm install
    ```
3.  Создайте файл конфигурации `.env` на основе примера:
    ```bash
    cp .env.example .env
    ```
4.  Заполните `.env` вашими токенами:
    ```env
    TELEGRAM_BOT_TOKEN=ваш_токен_телеграм_бота
    GEMINI_API_KEY=ваш_ключ_gemini_api
    DB_PATH=data/bot_messages.db
    DEFAULT_TIMEZONE=Europe/Moscow
    BOT_LANGUAGE=ru
    ALLOW_ALL_CHATS=true
    REDACT_USER_IDENTITIES=false
    ```

### Тестирование работоспособности
Вы можете запустить полный встроенный набор тестов перед основным запуском:
```bash
npm test
```
Он включает тесты базы данных, основных обработчиков, парсера времени, утилит и суммаризатора. Отдельные наборы можно запускать так:
```bash
npm run test:db
npm run test:main
npm run test:parser
npm run test:utils
npm run test:summarizer
```

### Компиляция проекта (TypeScript build)
Для сборки проекта в JavaScript используйте команду:
```bash
npm run build
```
Скомпилированные файлы сохраняются в директорию `dist/`.

### Запуск бота
Запустите бота в режиме прямого выполнения TypeScript-кода (с помощью `tsx`):
```bash
npm start
```
Или для запуска скомпилированной версии:
```bash
node dist/main.js
```

## 💡 Использование бота

1.  Добавьте бота в ваш групповой чат.
2.  Общайтесь в чате как обычно — бот будет сохранять сообщения в фоновом режиме.
3.  Чтобы получить суммаризацию сообщений, упомяните бота и укажите желаемый интервал времени в свободной форме:
    *   `@bot_username суммаризуй за последний час`
    *   `@bot_username сделай выжимку за 3 часа`
    *   `@bot_username что обсуждали за сегодня?`
    *   `@bot_username кратко за вчера`
    *   `@bot_username суммаризация за последние 2 дня`
    *   `@bot_username выжимка за последний месяц`
    *   `@bot_username summarize last 30 minutes` (также поддерживается базовый английский)

*Поддерживаемые интервалы: минуты, часы, дни, неделя, месяц, а также `сегодня` и `вчера`.*

*Примечание: Если период времени не распознан, бот по умолчанию сделает выжимку за последние 24 часа.*

В личном чате отправьте фразу-триггер вроде `суммаризуй за час` или `summarize the last hour`, чтобы получить выжимку сообщений, видимых в этом личном чате.

### Углублённые ответы (опционально)

При `DEEP_DIVE_ENABLED=true` вместо полной выжимки можно задать боту конкретный вопрос и получить точечный ответ по истории чата:
*   `@bot_username что мы решили по миграции?`
*   `@bot_username расскажи подробнее про вчерашний инцидент`
*   `@bot_username почему отложили деплой за последние 3 часа?` (таймфрейм ограничивает ответ этим окном)

Упоминание без вопросительного слова по-прежнему даёт обычную суммаризацию, так что привычное поведение не меняется.
